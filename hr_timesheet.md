# Timesheets — What a Timesheet Really Is, When Lines Are Created, and Where the Money Goes

> **Modules:** `hr_timesheet` (community core) + `timesheet_grid` (enterprise: grid UI, timer, validation) + `project_timesheet_holidays` (Time Off bridge) | **Path:** [`addons/hr_timesheet/`](../addons/hr_timesheet/)
> Related: [`geo_payroll.md`](geo_payroll.md), [`work_entries.md`](work_entries.md), [`payroll_wage_types.md`](payroll_wage_types.md)

## What It Is

There is no "timesheet" model. A timesheet is an **`account.analytic.line` whose `project_id` is set** — the same model that carries every analytic (cost-accounting) entry in Odoo. `hr_timesheet` extends it with `project_id`, `task_id`, `employee_id`, and the timesheet behaviors ([account_analytic_line.py](../addons/hr_timesheet/models/account_analytic_line.py) — in v20 this file replaces the old `hr_timesheet.py`). One line = one person / one date / one project(+task) / `unit_amount` hours / a money `amount`.

Because timesheets live in the analytic world, their money is **project cost accounting** — they never touch payroll, journals, or salaries by default.

## When Lines Are Created — every path

| # | Trigger | When exactly | Marker fields |
|---|---|---|---|
| 1 | Manual entry — task form "Timesheets" tab, Timesheets app grid/list | On save of the row | none |
| 2 | Systray / grid timer (enterprise) | In v20 the timer is **client-side only**: elapsed time lives in `localStorage`, no `timer.timer` record is written and the line no longer inherits `timer.mixin` ([account_analytic_line.py:21](../enterprise/timesheet_grid/models/account_analytic_line.py#L21), [static_timesheet_timer_service.js](../enterprise/timesheet_grid/static/src/services/static_timesheet_timer_service.js)). The line is created/updated when the timer form is saved or stopped | none |
| 3 | **Employee leave validation** (`project_timesheet_holidays`) | `hr.leave._validate_leave_request()` → `_generate_timesheets()` → `sudo().create()` — one line per working day of the leave, on the company's internal "Time Off" project/task. Leaves whose work entry type has `count_as = 'working_time'` are skipped ([hr_leave.py:13-78](../addons/project_timesheet_holidays/models/hr_leave.py#L13)) | `holiday_id` |
| 4 | **Public holiday creation** (same bridge) | Creating a `resource.calendar.leaves` generates internal-project lines for affected employees ([resource_calendar_leaves.py:260](../addons/project_timesheet_holidays/models/resource_calendar_leaves.py#L260)) | `global_leave_id` |
| 5 | **Timesheet Assistant** (enterprise, new in v20) | Proposes entries from the day's Odoo activity and, via the ActivityWatch bridge, from matched browser activity (`aw.rule` regex → template). Accepting a suggestion creates an ordinary line ([account_analytic_line.py:549](../enterprise/timesheet_grid/models/account_analytic_line.py#L549), [aw_rule.py:8](../enterprise/timesheet_grid/models/aw_rule.py#L8)) | none |
| 6 | Field Service / Helpdesk | Same manual/systray paths as #1/#2 on their tasks and tickets — the dedicated FSM and Helpdesk record timers of v19 no longer exist | — |
| 7 | (planned custom) `geo_payroll` OT-approval bridge | Would create a draft line per approved OT log — off in release 1 | `work_log_id` |

Paths 3 and 4 are the reason a payroll integration must **never** pay "all timesheets": leave and holiday lines are bookkeeping noise generated by sudo, not worked time.

## The Money — cost is booked immediately, at `hourly_cost`

On every create/write touching `unit_amount`, `employee_id`, or `account_id`, `_timesheet_postprocess_values()` recomputes:

```text
amount = − unit_amount × employee.hourly_cost        (converted to company currency)
```

([account_analytic_line.py:451-480](../addons/hr_timesheet/models/account_analytic_line.py#L451), cost source [account_analytic_line.py:504-506](../addons/hr_timesheet/models/account_analytic_line.py#L504))

- **Negative** = a cost on the project's analytic account (`account_id`, auto-filled from the project via `_timesheet_preprocess_get_accounts`, [account_analytic_line.py:424](../addons/hr_timesheet/models/account_analytic_line.py#L424)).
- `hourly_cost` is a core `hr` field in v20 — the separate `hr_hourly_cost` module is gone ([hr_employee.py:279](../addons/hr/models/hr_employee.py#L279)). It sits on the employee form's **Settings** tab, Application Settings group, and it is a **costing** rate (what an hour of this person costs the company), deliberately not the payroll wage.
- Analytic only: no journal entry, no payable, no payslip. It feeds analytic reporting and, on billable projects, invoicing quantities.

## Validation (enterprise `timesheet_grid`)

Managers validate periods in the grid → `validated=True` per line + `employee.last_validated_timesheet_date` advances, locking employees out of editing anything on or before that date ([account_analytic_line.py:249](../enterprise/timesheet_grid/models/account_analytic_line.py#L249), [hr_employee.py:43](../enterprise/timesheet_grid/models/hr_employee.py#L43)). Validation is the natural "manager approved these hours" gate — which is why the planned `geo_payroll_timesheet` bridge pays only validated lines.

## What Consumes Timesheets by Default

| Consumer | What it reads |
|---|---|
| Analytic reporting | the negative `amount` (costs) on the project's analytic account. `analytic_profitability` classifies a timesheet line as **Loss** — no general account, `category = 'other'`, negative amount ([account_analytic_line.py:98](../addons/account/models/account_analytic_line.py#L98)) |
| Sales invoicing (service products invoiced on timesheets) | `unit_amount` as delivered quantity; billable lines get `so_line` |
| Timesheet reports / grid | hours |
| **Payroll** | **nothing — no native link exists**. In v20 the `work_entry_source` selection was removed entirely, and the only work-entry producer is `hr.version._get_work_entries_values()` (calendar, leaves, attendance, planning — never analytic lines) ([hr_version.py:277](../addons/hr_work_entry/models/hr_version.py#L277)). Hourly-workers-from-timesheets is always a customization |

## Where to See the Project Cost

| Surface | Path | What you get |
|---|---|---|
| Timesheets reporting (no accounting rights needed) | Timesheets app → Reporting → group by Project, measure **"Timesheet Costs"** — the `amount` field exposed in the pivot/graph ([account_analytic_line_views.xml:69](../addons/hr_timesheet/views/account_analytic_line_views.xml#L69)) | Cost per project/employee/month |
| Project → Analytic Items | Project app → open project → **Analytic Items** embedded action (requires Analytic Accounting rights); the v19 Profitability block no longer exists ([project_project_views.xml:26](../addons/project_account/views/project_project_views.xml#L26)) | Every analytic line of the project, costs and revenues side by side |
| Analytic Items (raw ledger) | Accounting → Accounting → Transactions → Analytic Items, filter by the project's analytic account ([account_menuitem.xml:27](../addons/account/views/account_menuitem.xml#L27)) | Every individual line, the negative amounts themselves |

Prerequisite for any of it: the employee's **Hourly Cost** (employee form → Settings tab). If it is 0, every timesheet books a 0.00 cost and all three surfaces show hours but no money.

## Edge Cases & Gotchas

- Leave/holiday lines (`holiday_id` / `global_leave_id`) are created in sudo and can be swept up by validation; regeneration deletes them in sudo without recomputing `last_validated_timesheet_date` — the boundary can lock ordinary timesheets (see [`work_entries.md`](work_entries.md)). In v20 those lines are also `_is_readonly()` and non-sudo writes raise ([account_analytic.py:18](../addons/project_timesheet_holidays/models/account_analytic.py#L18)).
- `unit_amount` is always stored in **hours**, even when the company encodes timesheets in days.
- Changing the employee's `hourly_cost` does not rewrite historical line amounts (recompute fires only on line writes).
- An analytic line without `project_id` is not a timesheet — same table, none of the timesheet logic.

## What Changed in Odoo 20

- `models/hr_timesheet.py` → [`models/account_analytic_line.py`](../addons/hr_timesheet/models/account_analytic_line.py) and `views/hr_timesheet_views.xml` → [`views/account_analytic_line_views.xml`](../addons/hr_timesheet/views/account_analytic_line_views.xml). The `amount` compute itself is unchanged.
- The `hr_hourly_cost` module is gone; `hourly_cost` moved into core `hr` and the dependency was dropped from the manifest — [hr_employee.py:279](../addons/hr/models/hr_employee.py#L279), [\_\_manifest\_\_.py:21](../addons/hr_timesheet/__manifest__.py#L21)
- **Server-side timers were removed.** No model inherits `timer.mixin` any more (v19: `timesheet_grid`, plus `timer.parent.mixin` on tasks and helpdesk tickets). The timer is a browser-side systray widget backed by two read-only routes — [timesheet_systray_controller.py:41](../enterprise/timesheet_grid/controllers/timesheet_systray_controller.py#L41)
- **Project profitability was removed** from `project` and `sale_timesheet`. The project side now exposes an embedded **Analytic Items** action, and grouping by profit/loss is done with the new groupable `analytic_profitability` field on the analytic line — [project_project_views.xml:26](../addons/project_account/views/project_project_views.xml#L26), [account_analytic_line.py:51](../addons/account/models/account_analytic_line.py#L51)
- New **Timesheet Assistant**: `aw.rule` (ActivityWatch browser URL rules, seeded with GitHub/Gmail/Meet patterns) feeds daily suggestions, and `ai_timesheet_grid` layers AI on top — [aw_rule.py:8](../enterprise/timesheet_grid/models/aw_rule.py#L8), [aw_rule_data.xml](../enterprise/timesheet_grid/data/aw_rule_data.xml)
- Leave line generation now skips a leave when its **work entry type** has `count_as = 'working_time'` (v19 tested `holiday_status_id.time_type == 'other'`) — [hr_leave.py:30](../addons/project_timesheet_holidays/models/hr_leave.py#L30)
- Security rebuilt: `ir.model.access.csv` + `ir.model.access.xml` → one [`security/ir.access.csv`](../addons/hr_timesheet/security/ir.access.csv) loaded **last** in the manifest. Read on `timesheets.analysis.report` is no longer unconditional for `base.group_user` — it is gated on `has_department_manager_access`, own lines, or approver/manager groups.
- `work_entry_source` no longer exists anywhere in core, so the "payroll has no timesheet source" statement now holds by absence of the whole selection rather than by a missing option — [hr_version.py:277](../addons/hr_work_entry/models/hr_version.py#L277)
